### A.2 Version-specific constraints observed (from `node_modules/next/dist/docs/`)

`AGENTS.md` warns that this Next.js differs from common knowledge. The behaviours that actually affect this build:

- **Async request APIs are mandatory.** Synchronous access was fully removed in v16. `params`, `searchParams`, `cookies()`, `headers()` are all Promises and must be awaited.
- **Typed route helpers.** `PageProps<'/route/[param]'>` and `LayoutProps<'/route'>` are *globals* generated by `next dev` / `next build` / `next typegen` — no import needed. The existing `app/layout.tsx` already uses `LayoutProps<"/">`, so the project is on this convention.
- **Turbopack by default** — no `--turbopack` flag needed; a stray webpack config would break `next build`.
- **ESLint flat config** is the default; the existing `eslint.config.mjs` is already flat.
- **Scroll behaviour**: v16 no longer overrides `scroll-behavior` on navigation unless `data-scroll-behavior="smooth"` is set on `<html>`.
- `not-found.js`, `loading.js`, `error.js` conventions unchanged; `error.js` must be a Client Component.

**Reused as-is (not replaced):**

- Next.js App Router + TypeScript + Tailwind v4 setup, including `@theme inline` token style in `globals.css`.

- `components/` tree, `lib/` domain modules, `lib/actions/` server actions.
- E-commerce Prisma models + a new migration + a seed script.
- Assets copied from `shop.co/` into `public/`.

**Deliberately not added:** no second CSS framework, no component library, no state library, no animation library, no validation library. Password hashing uses **`node:crypto` `scrypt`** so the build adds **zero new runtime dependencies**.

## C. Page / Route Plan

The project has no established routing to preserve beyond `/`, so the requested route list is adopted with two deliberate adjustments, both noted below.

| Route | Rendering | Purpose |
| --- | --- | --- |
| `/` | Server | Home: hero, brand strip, New Arrivals rail, Top Selling rail, dress-style grid, testimonials |
| `/shop` | Server | Full catalogue: filters, sort, pagination |
| `/shop/[category]` | Server | Resolves **either** a product category (`t-shirts`, `shirts`, `jeans`, `shorts`) **or** a collection (`new-arrivals`, `top-selling`, `on-sale`) through one resolver → `notFound()` otherwise |
| `/product/[slug]` | Server | Gallery, purchase panel, tabs (details / reviews / FAQ), related products |
| `/cart` | Server | Line items, quantity control, promo code, totals |
| `/checkout` | Server + action | Address form → creates a real `Order` row |
| `/checkout/success/[orderNumber]` | Server | Confirmation, ownership-checked |
| `/search` | Server | `?q=` results, reuses the shop grid |
| `/wishlist` | Server | Saved items (**requires sign-in**) |
| `/login` | Server + action | Real credential sign-in, honours `?next=` |
| `/register` | Server + action | Real account creation |
| `/account` | Server | Profile summary + sign-out |
| `/account/orders` | Server | Order history |
| `/account/orders/[orderNumber]` | Server | Order detail |
| `not-found.tsx` | Server | 404 using `images/states/not-found.png` |
| `error.tsx` | Client | Root error boundary |
| `loading.tsx` (root, `/shop`, `/product/[slug]`) | Server | Skeleton streaming states |

**Adjustment 1 — collections live under `/shop/[category]`.** The reference's "New Arrivals / Top Selling / On Sale" nav items are in-page scroll anchors on the home route, which are not real pages and break deep-linking. They become real, indexable routes that share the shop resolver, so breadcrumbs, filters, sorting and pagination work identically on all of them.

**Adjustment 2 — dress styles are query filters, not routes.** `Casual / Formal / Party / Gym` map to `/shop?style=casual` etc., because they compose with the other filters. All filter and sort state lives in the URL (`?category=&style=&color=&size=&min=&max=&sort=&page=`) so results are shareable, back-button-correct, and server-rendered.

### C.1 Authentication and the cart gate

Per the decision taken before implementation: **adding to cart requires a real signed-in account.**

- `User` gains `passwordHash`; a new `Session` table holds SHA-256 hashes of opaque 32-byte random tokens with an expiry.
- Hashing is `node:crypto` **scrypt** (N=16384, r=8, p=1) with a per-user 16-byte salt, compared with `timingSafeEqual`. No new dependency, no `AUTH_SECRET` to manage — the token is random, not signed.
- Cookie: `session`, `httpOnly`, `sameSite=lax`, `secure` in production, 30-day `maxAge`, `path=/`.
- `addToCart`, `toggleWishlist`, `checkout` and `submitReview` all call `requireUser()`. When there is no session the server action `redirect()`s to `/login?next=<current path>`; after a successful sign-in the user lands back where they were.
- The cart is a **server-side `CartItem` table keyed by user**, not `localStorage` — so it survives across devices and is consistent with the login gate.

## E. Design System

Encoded as CSS custom properties in `app/globals.css` under Tailwind v4's `@theme inline`, so everything is reachable as a Tailwind utility.

### Typography

| Role | Family | Usage |
| --- | --- | --- |
| Display | **Integral CF Bold** (`--font-display`), loaded with `next/font/local`, `display: swap` | `SHOP.CO` wordmark, hero headline, all-caps section headings |
| Body | **Geist** (`--font-geist-sans`) — *already in the project* | everything else |
| Mono | Geist Mono — *already in the project* | order numbers |

Scale (mobile → desktop): hero `text-4xl` → `text-6xl`; section heading `text-3xl` → `text-5xl`; product title `text-base` → `text-xl`; body `text-sm` → `text-base`; meta `text-xs` → `text-sm`. Weights: 400 body, 500 links/labels, 700 prices/product names, display face carries its own bold.

### Colour

| Token | Value | Use |
| --- | --- | --- |
| `--color-ink` | `#000000` | primary text, buttons, brand bar |
| `--color-ink-muted` | `rgb(0 0 0 / 0.60)` | body copy, breadcrumb parents |
| `--color-ink-subtle` | `rgb(0 0 0 / 0.40)` | struck-through prices, meta |
| `--color-surface` | `#ffffff` | page |
| `--color-surface-muted` | `#f0f0f0` | product tiles, inputs, chips |
| `--color-line` | `rgb(0 0 0 / 0.10)` | hairlines, card borders |
| `--color-sale` | `#ff3333` | discount badge text |
| `--color-sale-soft` | `#ffebeb` | discount badge background |
| `--color-star` | `#ffc633` | rating stars |

The reference site is light-only and the design depends on true black on white, so the storefront **commits to a single light palette**. The starter's `prefers-color-scheme` block is removed rather than left half-implemented.

### Spacing, radius, shadow

- Page gutter: `1rem` → `1.5rem` (≥400px) → `6rem` (≥768px), exposed as a `.container-page` utility (mirrors the reference's `mainPadding`).
- Section rhythm: `py-10` mobile → `py-16` desktop; rails and grids use a 24px gap.
- Radius: `rounded-full` for buttons/chips/inputs (the signature SHOP.CO shape), `rounded-2xl` for product tiles and cards, `rounded-3xl` for the newsletter and footer blocks.
- Shadows: essentially none — the design separates with `--color-line` hairlines and `--color-surface-muted` fills. Only the sticky header gets a `shadow-sm` once scrolled.

### Components

- **Button** — variants `primary` (black fill, white text), `secondary` (white fill, hairline border), `ghost`; sizes `sm`/`md`/`lg`; all `rounded-full`, `min-h-11` (44px touch target), visible `focus-visible` ring, `disabled:opacity-50`.
- **Input** — `rounded-full`, `bg-surface-muted`, no border, `outline-none` + `focus-visible` ring; always paired with a real `<label>` (visually hidden where the design has none).
- **Product card** — square `--color-surface-muted` tile, `next/image` with `sizes`, `object-contain` and internal padding so the 300×300 cut-outs are never cropped or stretched; title, stars + numeric rating, price row with strike-through and `-N%` badge.

### Breakpoints and intentional responsive behaviour

Tailwind defaults plus one custom `xs: 400px` (the reference's `xsm`). The desktop layout is **not** merely shrunk:

| Area | < 640px | 640–1023px | ≥ 1024px |
| --- | --- | --- | --- |
| Header | logo + search icon + cart + hamburger; search collapses to its own row | logo + inline search + icons | full nav + search + icons |
| Navigation | full-height slide-in drawer, focus-trapped | drawer | inline nav with dropdown |
| Product grid | 2 columns | 3 | 4 |
| Home rails | horizontal scroll-snap, edge-bleed | scroll-snap | 4-up grid |
| Filters | bottom-sheet drawer behind a "Filters" button | drawer | 295px sticky sidebar |
| Gallery | main image, thumbnails in a row beneath | same | thumbnail column at left |
| Cart | stacked: lines then summary | stacked | 2-column, sticky summary |
| Checkout | single column | single column | form + sticky summary |
| Footer | accordion-free stacked columns | 2 columns | 5 columns |

Hero uses `text-balance`; every tap target is ≥44px; nothing depends on hover alone.

## G. Data Model

New models in `prisma/schema.prisma` (`User` is extended in place; the existing migration is untouched and a new one is added):

```
User          + passwordHash, sessions[], cartItems[], wishlist[], orders[], reviews[]
Session       tokenHash @unique, userId, expiresAt
Category      slug @unique, name, position → products[]
DressStyle    slug @unique, name  ⇄ Product   (implicit m-n)
Color         slug @unique, name, hex, position ⇄ Product
Size          slug @unique, name, position ⇄ Product
Product       slug @unique, name, description, details, priceCents,
              compareAtPriceCents?, rating, reviewCount, isNewArrival,
              isTopSelling, categoryId, images[], reviews[]
ProductImage  productId, url, alt, blurDataUrl, position
Review        productId, userId?, authorName, rating, title, body, createdAt
Testimonial   authorName, body, rating, isVerified, position
CartItem      userId, productId, colorId, sizeId, quantity  @@unique(all four)
WishlistItem  userId, productId  @@unique([userId, productId])
PromoCode     code @unique, percentOff, isActive, expiresAt?
Order         orderNumber @unique, userId, status, contact + address fields,
              subtotalCents, discountCents, shippingCents, totalCents, promoCode?
OrderItem     orderId, productId?, name, slug, imageUrl, colorName, sizeName,
              unitPriceCents, quantity
enum OrderStatus { PENDING PAID SHIPPED DELIVERED CANCELLED }
```

`CartItem` makes `colorId` and `sizeId` **required** — Postgres treats `NULL`s as distinct in unique indexes, so a nullable variant key would silently allow duplicate lines. The purchase panel therefore requires a colour and a size before "Add to Cart" is enabled, which also matches the reference UX.

`OrderItem` denormalises name/slug/image/price at purchase time so historical orders stay correct if the catalogue changes; `productId` is nullable with `onDelete: SetNull`.

## H. Known constraints going in

These are limits of the available material, recorded now so they are not mistaken for defects later:

1. **One image per product.** `shop.co` ships a single 300×300 cut-out per garment. The gallery is built to render 1..n images and only shows the thumbnail strip when `images.length > 1` — no duplicate-image fake gallery.
2. **Hero source is 390×496.** It is the only hero asset available; the layout caps its rendered size so it is not visibly upscaled, but it cannot be sharper than its source.
3. **No payment processing.** Checkout persists a real `Order` at status `PENDING`. No card fields are collected and no processor is contacted.
4. **Colour variants are seeded demo data.** Only one photographed colourway exists per garment, so selecting a different swatch does not change the photo. The selected colour is still stored on the cart line and the order item.
5. **Newsletter subscription** stores the address in a `NewsletterSubscriber` table; no email is actually sent (no mail provider configured).
6. **No test runner exists** in the project. Section 11's `pnpm test` has no counterpart; verification is `lint`, `typecheck` (`tsc --noEmit`), `build`, plus scripted route checks against a running server. A `typecheck` script will be added since it is missing.
7. The demo font licence caveat in §B.2.

## J. Deltas from the plan

| Plan said | What shipped | Why |
| --- | --- | --- |
| `src/Svgs/Vector.svg` is a true vector for the hero star | It was another base-64 PNG wrapper. The star silhouette was **traced from the 104×80 alpha channel and refitted as four cubic Béziers** → `public/images/hero/star.svg`, 253 bytes, 1 % mean deviation from the original | The provided "SVG" was raster; the star is a pure geometric form, so a true vector is a strict improvement and scales to any size |
| Cart/wishlist gated behind sign-in | Same, plus **`Session` + scrypt credentials** and a full `/login` `/register` `/account` flow | The decision taken before building was real credential auth with a login-gated cart |
| Zero new dependencies | **`tsx` added as a devDependency** | The Prisma 7 `prisma-client` generator emits TypeScript with extensionless imports, which plain `node` cannot resolve. `tsx` is Prisma's documented seed runner. It is dev-only and not in the runtime bundle |
| `generateStaticParams` on `/product/[slug]` | **Removed** | The header reads the session cookie, so every route renders dynamically. The build confirmed no product page was prerendered (`prerender-manifest.json` listed none), making the build-time query pure waste. | Promo code applied via a server action | **Plain `GET` form to `/cart?promo=`** | Simpler, works without JavaScript, and keeps the applied code in the URL so `/cart` and `/checkout` agree. The discount is still recomputed server-side before any order is written |
| Search via `router.push` | **Plain `GET` form to `/search`** | Works with and without JavaScript |
| Account pages guarded by `app/account/layout.tsx` | **Each page guards itself** via `requireUserOrRedirect` | Layouts and pages render *in parallel*, so the layout's `redirect()` did not stop its pages executing — this threw a real `TypeError` on every signed-out `/account` request. ## K. Two defects found by verification and fixed

**1. The homepage scrolled sideways into blank space.** At 390 px the document was 1273 px wide. Bisecting showed the horizontal rails' scrollable area leaking into the document's own scroll width. Neither `overflow-x: hidden` nor `clip` on `html`/`body` stopped it; `contain: paint` on the scroller did. The `rail-scroll` utility now carries `contain: paint`, and rails that become grids at `lg` opt out with `lg:[contain:none]`. Verified: 18/18 route × viewport combinations now have zero horizontal scroll, with the sticky header and rail scrolling both intact.

**2. The display font printed a "DEMO" badge instead of a hyphen.** The Fontspring demo build of Integral CF replaces most punctuation — and the digit `4` — with a watermark glyph, so *"ONE LIFE GRAPHIC T-SHIRT"* rendered a DEMO badge mid-word. A rendered specimen established the usable set: `A–Z`, `0–3`, `5–9`, space, `,` `.` `:` `;` `?`. The `@font-face` now carries a `unicode-range` restricted to exactly those, so every other character falls back to Geist invisibly. Order numbers were additionally moved to the mono face. Removing the `declarations` block is the whole change needed to drop in a licensed Integral CF.

## M. Known limitations

1. **No payment processing.** Checkout writes a real `Order` at status `PENDING`. No card details are collected and no processor is contacted. The checkout page and the confirmation page both say so in plain language.
2. **No test runner.** The project had none and adding a framework was outside this task's scope. Verification was done with the scripted suites described above; they live in the session scratchpad, not the repo. Adding Vitest + Playwright is the natural next step.
3. **One photograph per product.** `shop.co` ships a single 300×300 cut-out per garment. `ProductGallery` renders 1..n images and shows the thumbnail strip only when there is more than one — no gallery faked by repeating the same image.
4. **Colour variants are seeded demo data.** Only one colourway was photographed per garment, so choosing another swatch does not change the photo. The choice is still validated server-side against the product and stored on the cart line and order item.
5. **Hero image is a 390×496 source** displayed at ~612 px on desktop, so it is slightly soft. It is the only hero asset available.
6. **Newsletter stores the address only.** No mail provider is configured, so nothing is sent; the confirmation says only that the address was saved.
7. **Font licence.** The bundled Integral CF is a Fontspring *demo*, normally evaluation-only. A commercial launch needs a purchased licence or a substitute.
8. **Every route renders dynamically**, because the header personalises per session. Enabling `cacheComponents` (PPR) would restore prerendered shells with the personalised parts streamed in.
